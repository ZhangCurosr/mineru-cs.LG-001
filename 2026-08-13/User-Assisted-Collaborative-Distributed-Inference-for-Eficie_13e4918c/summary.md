# 论文速读：User-Assisted Collaborative Distributed Inference for Efficient QoS-Aware Autoscaling

## 一句话总结
提出了一种协作式分布式AI推理系统，将推理计算拆分到专用服务器和用户的志愿设备上；通过高维生成马尔可夫模型捕捉动态交互，证明随着用户规模增长，分布式调度比集中式推断在请求完成率、P99延迟和资源效率上均显著更优。

## 研究问题与动机
1. **AI推理成本激增**：2025年全球AI投资达5816.9亿美元，推理成本已超过一次性训练成本，且集中式云计算的成本与环境负担随需求线性增长。
2. **边缘/雾计算部署受限**：现有边缘AI方案依赖预定义基础设施，无法利用大量闲置的个人/机构设备，且计算连续体仍存在架构与经济壁垒。
3. **志愿计算缺乏QoS保障**：传统志愿计算因资源异构性和间歇可用性，难以提供稳定的服务质量，不适用于面向消费者的AI推理服务。
4. **缺少建模与分析工具**：用户、资源、任务与策略之间存在复杂的随机动态交互，现有方法缺乏统一的仿真框架来支撑调度策略评估与优化。

## 核心贡献（创新点）
1. **协作式分布式推理架构**：将推理拆分到专用服务器与用户志愿设备，专用资源提供基线容量保障QoS，志愿资源吸收增长需求，避免中心化基础设施的线性扩张；与纯集中式推断的本质区别在于不再需要专用容量随需求同比例增长。
2. **高维生成马尔可夫模型**：构建了结构化时序因式分解的生成马尔可夫模型，通过稀疏依赖性建模用户可用性、请求提交、资源分配、子任务准备与执行等状态变量；与已有工作[12]相比，本文首次将该框架应用于AI推理场景并包含详细的参数化实现。
3. **三种调度策略设计与评估**：提出集中式、均匀分布式与亲和性调度策略，并在用户规模（100-10,000）、资源容量（10×-100×）等多维度下仿真对比；与已有工作（如[26][27][28]）不同，本文聚焦于结合志愿资源的自动伸缩，而非仅优化预定义边缘基础设施。
4. **实证验证分布式方案优势**：在10,000用户规模下，均匀调度相比集中式显著降低P99延迟并减少约三分之二的专用CPU消耗，且30×-50×专用容量已足够配合志愿资源；这一量化结论填补了"志愿计算能否支撑AI推理"的空白。

## 方法详解

### 系统架构
- **节点集合**：$V = \{v_0\} \cup \mathcal{T}$，其中$v_0$为专用服务器（始终在线），$\mathcal{T}$为用户集合（志愿设备）。
- **任务类型**：$k \in \mathcal{K}$，每种任务由子任务集合$\mathcal{P}_k$组成。
- **决策策略**：调度器策略$\pi$（服务器端）与执行器策略$\varsigma$（节点端），联合动作$\mathbf{u}_t = \langle \mathbf{u}_t^{\pi}, \mathbf{u}_t^{\varsigma} \rangle$。

### 状态变量设计
系统状态$\mathbf{s}_t = \langle \mathbf{o}_t, \mathbf{q}_t, \mathbf{a}_t, \mathbf{x}_t, \mathbf{y}_t, \mathbf{c}_t, \mathbf{d}_t, \mathbf{u}_t \rangle$：

1. **可用性状态** $\mathbf{o}_t$：用户在线指示$\mathbf{o}_t \in \{0,1\}^{|\mathcal{T}|}$与持续时间$\mathbf{d}_t^o$；采用Weibull（在线，中位数10分钟）和Log-normal（离线，中位数1.5小时）生存函数。
2. **推理请求** $\mathbf{q}_t$：用户活动请求类型$k \in \mathcal{K} \cup \{k_0\}$与持续时间$\mathbf{d}_t^q$；采用Pareto生存函数（$\kappa=30s, \alpha=1.5$），模拟重尾think time与patience。
3. **分配资源** $\mathbf{a}_t$：每个节点各类资源（band in/out, cpu, memory, storage）的分配量；使用ARMA模型捕捉自相关性，参数由MacBook M4 Pro实测数据拟合。
4. **子任务就绪状态** $\mathbf{x}_t$：$\{\text{empty, download, pause, ready}\}$；含辅助状态与持续时间，描述数据下载进度。
5. **子任务执行状态** $\mathbf{y}_t$：$\{\text{idle, download, execution, upload, done}\}$；采用离散时间风险模型拟合各阶段完成概率。
6. **资源消耗** $\mathbf{c}_t$：分为数据准备消耗$\mathbf{c}_t^x$（无storage）与执行消耗$\mathbf{c}_t^y$（无memory）；ARMA模型建模，考虑带宽与批处理效应。

### 调度策略
- **集中式**：所有子任务在服务器$v_0$执行，不调度用户节点下载。
- **均匀调度**：随机将子任务分配给在线且内存足够的节点，最大化志愿资源利用率。
- **亲和性调度**：优先将相同子任务调度到已有同类执行的节点，以增大batch size，但可能增加中断风险。

### 优化问题
1. **调度优化**：$\max_\pi \liminf_{T\to\infty} \mathbb{E}[\frac{1}{T}\sum_{t=1}^T r(\mathbf{s}_t)]$，奖励$r(\mathbf{s}_t) = -\mathbf{1}^\top \delta(\mathbf{q}_t, \mathbf{d}_t^q)$最小化平均延迟。
2. **资源分配优化**：$\min_{\mathbf{a}_\dagger} \|\mathbf{a}_\dagger\|_\mathbf{w}$，约束P99延迟低于阈值$\tau_k$（置信度$1-\epsilon_k$）。

## 实验与结果

### 实验设置
- **硬件平台**：MacBook M4 Pro（24GB RAM, 512GB storage）。
- **任务类型**：4种（light-5子任务, light-10子任务, heavy-5子任务, heavy-10子任务），概率分别为0.4, 0.3, 0.2, 0.1。
- **用户规模**：100, 1,000, 5,000, 10,000。
- **用户容量**：1×, 2×（基线：100 Mbit带宽, 3GB storage, 2.5GB memory, 200% CPU）。
- **服务器容量**：10×, 30×, 50×, 80×, 100×（基线内存25GB）。
- **仿真长度**：100,000步（约28小时）。

### 关键结果

**1. 请求完成率（Fig. 2）**
- 集中式：10×容量下仅支撑约1,000用户后饱和，10,000用户时取消率高达33%-50%。
- 均匀调度：10,000用户下在所有容量配置（包括100×）均优于集中式；2×用户容量时5,000用户规模即显著领先。
- 亲和性调度：批量效率提升但中断风险高，10,000用户下完成率最差。

**2. P99延迟（Fig. 3）**
- 1,000用户内：集中式与均匀调度相当。
- 5,000用户、30×容量：均匀调度开始超越集中式。
- 10,000用户：均匀调度P99延迟显著低于集中式；集中式延迟跨任务类型波动大。
- 30×-50×容量后：分布式策略延迟改善趋于饱和。

**3. 专用资源消耗（Fig. 4）**
- 集中式：CPU在所有容量下饱和；10×容量时内存需求达50GB（两倍分配），导致abort。
- 均匀调度：30×容量时CPU与内存均远低于上限；50×-100×仅小幅增长。
- 亲和性调度：略优于均匀调度（约5%内存节省），但延迟更高。

**4. 子任务完成率（Fig. 5）**
- 服务器侧：集中式在10,000用户、10×容量时完成率仅约0.2；均匀调度在30×容量下接近完美。
- 用户侧：均匀调度完成率0.75-0.95，随用户容量提升；亲和性调度在1,000用户以下表现良好，用户数增加时下降（尤其弱节点）。

### 最强结果
在10,000用户、2×用户容量、30×服务器容量配置下，均匀调度相比集中式：
- P99延迟降低约40%-60%
- 专用CPU消耗减少约66%
- 请求取消率降低约50%

## 局限性与未来方向
1. **用户同质化假设**：假设所有用户具有相同的可用性与资源分布，实际部署需考虑用户异质性与公平性机制。
2. **状态空间平方增长**：执行状态随用户数平方增长，当前通过有限槽位线性化；请求中心表示可进一步压缩。
3. **仅评估固定策略**：本文未实现调度器优化或资源分配优化算法，仅对比三种启发式策略；需结合强化学习等方法求解优化问题(2)(3)。
4. **单服务器架构**：未考虑多专用服务器协同，可扩展至多数据中心场景。
5. **安全与隐私缺失**：志愿计算涉及用户数据安全与隐私保护，本文未讨论相关机制。
6. **工作负载局限**：目前针对静态计算图CV任务，可延伸至LLM自回归推理与DAG工作流。

## 研究启发与可借鉴点
1. **生成马尔可夫建模方法论**：结构化状态变量+稀疏时序因式分解的高维建模思路可迁移至其他分布式系统仿真，特别是包含异构动态资源的场景。
2. **生存函数刻画用户行为**：Weibull/Log-normal建模可用性、Pareto建模请求间隔，提供了基于实测数据的参数化流程，可直接复用于其他用户行为建模工作。
3. **ARMA+风险模型的资源消耗建模**：将资源消耗分解为时序自相关+阶段风险模型，兼顾准确性与可计算性，适用于分布式系统的细粒度仿真。
4. **专用+志愿混合架构设计**：专用资源保底QoS+志愿资源吸收增长的思路，可推广至其他成本敏感型服务（如边缘存储、分布式训练数据预处理）。
5. **batch size与中断风险的权衡**：亲和性调度通过增大batch提升效率但增加中断耦合风险，这一权衡机制对分布式批处理系统设计具有参考价值。

## 关键术语表
**Generative Markov Model**：通过因式分解的状态转移概率生成系统轨迹的建模框架，支持高维稀疏依赖的 tractable 仿真与推断。

**QoS-Aware Scheduling**：以服务质量（如延迟分位数、完成率）为约束或优化目标的资源调度策略。

**Volunteer Computing**：利用分散的、自愿贡献的计算资源（如个人设备）执行共享计算任务的范式。

**Pareto Survival Function**：具有重尾特性的生存函数，用于模拟交互式系统中较长的think time与patience分布。

**Discrete-Time Hazard Model**：离散时间风险模型，用于预测子任务各阶段（下载/执行/上传）在给定持续时间后的完成概率。

**ARMA Model**：自回归滑动平均模型，用于捕捉资源分配与消耗的时序自相关性。

**Subtask Batching**：将相同节点、子任务类型和执行年龄的子任务分组并行执行，以提升资源利用率但可能增加耦合延迟。

**Affinity-Based Scheduling**：优先将相同子任务调度到已有同类执行任务的节点，以增大batch size的启发式策略。
